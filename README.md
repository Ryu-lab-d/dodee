# DoDee - ระบบจัดการหอพัก/บ้านเช่า/คอนโด

โครงสร้างเริ่มต้น (Foundation) ตามสเปกใน Section 1-7 ประกอบด้วย backend API + frontend
พร้อมฐานข้อมูลครบทั้ง 9 ตาราง และ CRUD หลักสำหรับ ทรัพย์สิน/ห้อง/ผู้เช่า + ระบบ login แบ่งสิทธิ์ตาม role

## โครงสร้างโปรเจกต์

```
backend/    Node.js + Express + Sequelize (PostgreSQL)
frontend/   Next.js 16 + TypeScript + Tailwind CSS
docker-compose.yml   PostgreSQL สำหรับ dev
```

## สิ่งที่ทำเสร็จแล้ว

- Database schema ครบ 9 ตาราง: Users, Properties, Rooms, Tenants, MeterReadings, Invoices,
  Payments, Transactions, Notifications (+ UserProperty สำหรับ assign พนักงานเข้าทรัพย์สิน)
- Auth: JWT login, สร้าง user โดย owner เท่านั้น, แบ่งสิทธิ์ตาม role (owner/staff/accountant)
- Property/Room/Tenant CRUD API + หน้าเว็บ (list, add, detail)
- Dashboard summary API + หน้าแดชบอร์ด (จำนวนทรัพย์สิน, ผู้เช่า, รายรับเดือนนี้, ค้างชำระ, สถานะห้อง)
- Owner เห็นทุกทรัพย์สินของตัวเอง, staff/accountant เห็นเฉพาะทรัพย์สินที่ถูก assign
- **Module 2 - ระบบจดมิเตอร์**: หน้า "จดมิเตอร์" แสดงรายการห้องของเดือนที่เลือก + สถานะจดแล้ว/ยังไม่จด,
  กรอกเลขมิเตอร์ปัจจุบัน ระบบคำนวณหน่วยที่ใช้เอง (เทียบกับครั้งก่อนหรือค่าตั้งต้นของห้อง),
  กันค่าลดลง และเตือนถ้าตัวเลขกระโดดผิดปกติ (OCR ยังเป็น stub - รองรับ field แต่ยังไม่ implement)
- **Module 3 - Billing engine**: หน้า "บิล & การชำระเงิน" ปุ่ม "สร้างใบเรียกเก็บของเดือนนี้" จะดึงค่ามิเตอร์ของเดือนนั้น
  มาคำนวณ ค่าเช่า + ค่าน้ำ + ค่าไฟ (ตามอัตราต่อทรัพย์สิน) เป็นใบเรียกเก็บอัตโนมัติ, ตั้ง due date ล่วงหน้าตาม `INVOICE_DUE_DAYS`,
  และ auto-flip เป็น "ค้างชำระ" เมื่อเลยกำหนดโดยไม่ต้องมี cron job
- **Module 4 - Payment tracking**: บันทึกการชำระเงินต่อใบเรียกเก็บ (โอน/QR/เงินสด) จากหน้าเดียวกัน,
  เปลี่ยนสถานะใบเรียกเก็บเป็น "ชำระแล้ว" และสร้างรายการรายรับใน Transactions ให้อัตโนมัติ (ทั้งหมด atomic ผ่าน DB transaction)
  พร้อม API ลบการชำระเงิน (unmark) สำหรับกรณีบันทึกผิด
- **แยกหน้าหอพัก vs บ้าน/คอนโด**: เมนู "หอพัก" (`/properties`) สำหรับทรัพย์สินหลายห้อง จัดการห้องแยกรายห้องแบบเดิม
  ส่วนเมนู "บ้าน & คอนโด" (`/houses`) สำหรับทรัพย์สินยูนิตเดียว หน้าตาเรียบง่ายกว่า ไม่ต้องมีตารางห้อง
  (เบื้องหลังยังใช้ Room เดิม แต่สร้าง Room "หลัก" ให้อัตโนมัติ เพื่อให้ยังผูกกับระบบจดมิเตอร์/บิล/ผู้เช่าได้เหมือนกัน)
- **รูปภาพ + รายละเอียดเพิ่มเติม**: ทั้งทรัพย์สินและห้อง เพิ่มรูปได้หลายรูป (อัปโหลดผ่าน backend เก็บไฟล์ไว้ที่
  `backend/uploads/` เสิร์ฟผ่าน `/uploads/...`) และเพิ่มคำอธิบาย + รายการรายละเอียดแบบ label/value ได้ไม่จำกัดจำนวน
  (เก็บเป็น JSONB คนละคอลัมน์ ไม่ต้องแก้ schema ทุกครั้งที่อยากเพิ่ม field ใหม่)
- **ที่อยู่ + แผนที่**: แขวง/ตำบล, เขต/อำเภอ, จังหวัด, รหัสไปรษณีย์ + ปักหมุดพิกัดบนแผนที่ (Leaflet/OpenStreetMap ฟรี ไม่ต้องมี API key)
- **เลือกผู้เช่าจากหน้าทรัพย์สินได้โดยตรง** ไม่ต้องไปหน้า "ผู้เช่า" แยก
- **หน้าตาใหม่**: เมนูย้ายขึ้นด้านบนเป็นไอคอนกราฟิก (lucide-react) แทนอิโมจิ, โลโก้ใหญ่ขึ้น, มีหน้า splash โหลดตอนเข้าเว็บ
- **Module 6 - ระบบแจ้งเตือน**: ทำงานจริงแล้ว ไม่ใช่ stub - cron รันทุกวัน 8 โมงเช้า เช็คสัญญาใกล้หมดอายุ (30 วันก่อน)
  และบิลค้างชำระ สร้าง in-app notification (กระดิ่งมุมขวาบน) + ส่งเข้า LINE ให้ owner/staff ที่เกี่ยวข้อง มี dedup กันแจ้งซ้ำ
- **LINE OA เต็มรูปแบบ**: เชื่อมบัญชี LINE ส่วนตัวผ่านรหัสลิงก์ (webhook), ตั้งค่า Channel Token/Secret ผ่านหน้าเว็บ
  (มีคู่มือขั้นตอนละเอียดในตัว), ส่งข้อความแบบการ์ด (Flex Message) พร้อมปุ่มลิงก์กลับเข้าแอป
- **บันทึกการประชุม (ใหม่ทั้งหมด)**: บันทึก + เลือกผู้รับ + ส่งเข้า LINE เป็นการ์ดอัตโนมัติ พร้อม popup แอนิเมชันยืนยันสำเร็จ
- **Module 5 - รายรับ-รายจ่าย**: หน้า "รายรับ-รายจ่าย" กรอกรายการเองได้ (ไม่ใช่แค่รายรับจากค่าเช่าอัตโนมัติ),
  สรุปรายรับ/รายจ่ายรวม + กำไร-ขาดทุนตามช่วงเดือน/ทรัพย์สิน, export เป็น CSV (เปิดใน Excel ได้)
- **Module 8 - พนักงาน & สิทธิ์**: หน้า "พนักงาน" สร้างบัญชี, กำหนดบทบาท, มอบหมายทรัพย์สิน, เปิด/ปิดใช้งานบัญชี
  + Activity Log บันทึกว่าใครทำอะไรเมื่อไหร่ (สร้าง/แก้ทรัพย์สิน, เพิ่มผู้เช่า, ออกบิล, ชำระเงิน ฯลฯ)
- **Module 9 - ตั้งค่า**: ข้อมูลบริษัท (ชื่อ/โลโก้/ที่อยู่/เบอร์โทร ใช้บนใบเรียกเก็บ), เปลี่ยนรหัสผ่าน, ตั้งค่า LINE OA
- **ใบเรียกเก็บ**: ปุ่ม "ยกเลิกการชำระเงิน" (unmark) ใช้งานได้จริงแล้ว, มีหน้าพิมพ์/พรีวิวใบเรียกเก็บ (กด "พิมพ์" ต่อแถว)

## ยังไม่ได้ทำ (รอ Phase ถัดไป)

- OCR สแกนมิเตอร์ - ยังเป็น stub ตามที่ตกลงไว้ (ต้องใช้ API แบบเสียเงินอย่าง Google Vision)
- ใบเรียกเก็บยังไม่มีปุ่ม "ส่งซ้ำ" หรือ draft workflow (สร้างเป็น "issued" ทันที ไม่มีสถานะร่างให้แก้ก่อน)
- Export รายรับ-รายจ่ายเป็น PDF ยังไม่มี (มีแค่ CSV ซึ่งเปิดใน Excel ได้)
- จดมิเตอร์ยังทำได้ทีละห้อง ยังไม่มีโหมด "จดหลายห้องพร้อมกันในหน้าเดียว"
- Backup/Export ฐานข้อมูลทั้งระบบ และ Notification preferences (เปิด/ปิดการแจ้งเตือนเป็นรายคน) ยังไม่มี
- รูปภาพเก็บไว้บน local disk ของ backend เท่านั้น (ยังไม่ต่อ S3/Cloudinary) - ถ้า deploy จริงต้องย้ายไป cloud storage

## วิธีรันโปรเจกต์

### 1. เริ่ม PostgreSQL (ใช้ Docker)

```
docker compose up -d
```

หรือใช้ PostgreSQL ที่ติดตั้งเองแล้วก็ได้ แค่แก้ค่าใน `backend/.env`

### 2. Backend

```
cd backend
cp .env.example .env
npm install
npm run seed   # สร้าง owner account เริ่มต้น (username: owner / password: owner1234)
npm run dev    # รันที่ http://localhost:4000
```

### 3. Frontend

```
cd frontend
npm install
npm run dev    # รันที่ http://localhost:3000
```

เข้าสู่ระบบด้วย `owner` / `owner1234` ที่สร้างจาก seed script แล้วเริ่มเพิ่มทรัพย์สิน/ห้อง/ผู้เช่าได้เลย

## หมายเหตุด้านสถาปัตยกรรม

- ใช้ `sequelize.sync({ alter: true })` ในการสร้าง/ปรับตารางจาก model โดยตรงในช่วง foundation phase เพื่อความเร็ว
  ก่อนขึ้น production ควรเปลี่ยนเป็น migration files ผ่าน `sequelize-cli` เพื่อควบคุม schema change ได้ปลอดภัยกว่า
  (`alter: true` เหมาะกับ dev เท่านั้น เพราะบางกรณีอาจ drop/recreate index หรือ column แบบไม่ตั้งใจ)
- `properties_assigned` ในสเปกถูกออกแบบเป็นตาราง join (`UserProperty`) แทนการเก็บเป็น array
  เพื่อให้ query และ index ได้มีประสิทธิภาพกว่า
